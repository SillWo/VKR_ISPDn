# VKR_ISPDn

Веб-платформа для учёта и контроля ИСПДн в малом бизнесе.

Проект разрабатывается как дипломная работа. Цель системы — помочь организации вести реестр ИСПДн, хранить ключевые сведения по каждой системе, фиксировать процессы обработки персональных данных, определять уровень защищённости, учитывать технические меры защиты, задачи, несоответствия и документы.

## Основная идея

Центральная сущность системы — карточка ИСПДн.

Пользователь сначала открывает реестр ИСПДн, выбирает конкретную карточку, а затем работает с данными этой ИСПДн в связанных разделах:

- основные сведения;
- процессы обработки;
- уровень защищённости;
- модель угроз;
- технические меры защиты;
- задачи и несоответствия;
- документы.

Данные модулей относятся к конкретной ИСПДн, а не существуют отдельно от неё.

## Для кого система

Система ориентирована на микро- и малый бизнес, где есть один ИБ-специалист низкой или средней квалификации.

Платформа не является полноценной SGRC-системой. Это минимальный контур учёта и контроля ИСПДн для хранения данных, подготовки документов и отслеживания базовых несоответствий.

## Основные модули

### Реестр ИСПДн

Хранит карточки ИСПДн организации.

Позволяет видеть, какие ИСПДн есть в организации, какой у них статус и кто отвечает за обработку ПДн.

### Карточка ИСПДн

Хранит базовые сведения о конкретной ИСПДн:

- название ИСПДн;
- краткое описание;
- цели обработки ПДн;
- даты ввода и вывода в/из работы;
- сайт ИСПДн;
- ответственный за обработку ПДн;
- состав ИСПДн.

### Процессы обработки

Хранит сведения о том, какие персональные данные обрабатываются, на каком основании, в отношении каких субъектов и каким способом.

Этот модуль нужен в том числе для подготовки уведомления в Роскомнадзор об обработке ПДн.

### Уровень защищённости

Хранит данные, необходимые для определения уровня защищённости ИСПДн:

- категории обрабатываемых ПДн;
- категории субъектов ПДн;
- количество субъектов ПДн;
- тип актуальных угроз.

На основе этих данных система должна рассчитывать необходимый уровень защищённости.

### Технические меры защиты

Хранит сведения о рекомендуемых, реализованных, дополнительных и нереализованных технических мерах защиты.

Модуль использует выбранный уровень защищённости и матрицу рекомендуемых мер согласно Приказу ФСТЭК №21.

### Модель угроз

Потенциальный модуль.

На текущем этапе планируется как место хранения модели актуальных угроз ИСПДн. Система не разрабатывает модель угроз самостоятельно.

### Контрольные мероприятия

Потенциальный модуль.

Планируется для хранения контрольных мероприятий, ответственных, сроков, задач и отчётных документов.

### Задачи и несоответствия

Модуль для ручного и автоматического создания задач по контролю ИСПДн.

Задачи могут создаваться из-за незаполненных обязательных полей, необъяснённых несоответствий, нереализованных мер без пояснения и других проблем.

### Документация

Встроенный механизм генерации документов на основе уже сохранённых данных.

В будущем может быть расширен до отдельного реестра документов.

## Вспомогательные модули

### Карточка организации

Хранит сведения об организации:

- сокращённое название юридического лица;
- полное название юридического лица;
- ИНН;
- ОГРН;
- КПП;
- ФИО руководителя;
- должность руководителя;
- адрес регистрации;
- город регистрации.

### Реестр сотрудников

Хранит карточки сотрудников:

- ФИО;
- должность;
- подразделение.

Эти данные используются для указания ответственных в документах и модулях системы.

### Реестр целей обработки

Хранит цели обработки ПДн:

- название;
- период обработки.

Цели обработки используются в карточках ИСПДн и процессах обработки.

На этапе разработки Docker не используется.

Backend запускается через Python virtual environment.

Frontend запускается через Vite dev server.

PostgreSQL используется как локально установленная СУБД.

Docker Compose будет добавлен позже отдельной задачей для временного хостинга и демонстрации на защите.

## Локальный запуск

### 1. База данных

PostgreSQL должен быть установлен и запущен локально.

Пример переменной окружения находится в `.env.example`:

```env
DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/vkr_ispdn
VITE_API_BASE_URL=http://localhost:8000
```

Реальные `.env` файлы не должны попадать в Git.

### 2. Backend

```bash
cd backend
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Установка зависимостей:

```bash
pip install -r requirements.txt
```

Запуск backend:

```bash
uvicorn app.main:app --reload
```

После запуска backend должен быть доступен по адресу:

```text
http://localhost:8000
```

Документация API:

```text
http://localhost:8000/docs
http://localhost:8000/redoc
```

### 3. Frontend

```bash
cd frontend
npm install
npm run dev
```

После запуска frontend должен быть доступен по адресу, который покажет Vite в терминале.

Обычно это:

```text
http://localhost:5173
```

## Главный принцип разработки

Проект развивается поэтапно.

Одна задача должна изменять одну ограниченную часть системы.

Главный приоритет — сохранить понятную клиент-серверную архитектуру:

* backend предоставляет REST API;
* frontend работает с backend через HTTP-запросы;
* PostgreSQL хранит данные;
* данные процессов обработки, уровня защищённости, модели угроз и технических мер защиты принадлежат конкретной карточке ИСПДн.
